## 🚀 خطوات التشغيل (٥ دقائق)

### الخطوة 1 — افتح SQL Editor
1. ادخل على [supabase.com](https://supabase.com) وسجّل دخول.
2. افتح مشروعك (ZeroPlus).
3. من القائمة الجانبية اليسرى اختر **SQL Editor** ثم اضغط **New query**.

### الخطوة 2 — شغّل سكربت التجهيز
1. افتح ملف [`supabase/schema.sql`](./schema.sql) من المشروع وانسخه **كامل**.
2. الصقه في محرر SQL واضغط **Run** (أو `Ctrl+Enter`).
3. انتظر رسالة النجاح. السكربت آمن — تقدر تعيد تشغيله وقت ما تبي بدون ما يخرب شيء.

### الخطوة 3 — تحقق من النتيجة
اختر وحدة من هذي الطرق:

- **من داخل Supabase:** بنفس SQL Editor نفّذ:
  ```sql
  SELECT * FROM public.profiles LIMIT 5;
  ```
  ✔ إذا رجع جدول فارغ `[]` بدون خطأ → كل شيء تمام.
  ✘ إذا ظهر `permission denied` → السكربت ما اكتمل، أعِد تشغيله.

- **من التطبيق نفسه (الأفضل):**
  1. افتح الموقع في تبويب جديد (بعد نشر التحديث أو محلياً).
  2. سجّل اسمك في شاشة الترحيب.
  3. راقب النقطة الصغيرة أعلى الصفحة (مؤشر السحابة):
     - 🟢 أخضر = متصل والمزامنة تعمل ← **جاهز للإطلاق**
     - ⚪ رمادي = ما زالت المشكلة قائمة
  4. تأكد أيضاً من **Table Editor** في Supabase: بعد تسجيل الاسم لازم يظهر صف جديد في جدول `profiles` خلال ثوانٍ.

## 🔐 ملاحظات أمنية مهمة قبل الإطلاق

### 1) مفتاح anon معرّض بالكود — هذا طبيعي ✅
مفتاح `anon` مصمم أصلاً ليكون عام (يشتغل في المتصفح)، والحماية الحقيقية تجي من سياسات RLS.
السكربت المرفق فعّل RLS مع سياسات تسمح للمستخدم المجهول — وهذا مطلوب لأن التطبيق
يعتمد على `device_id` بدون تسجيل دخول.

**الوجه الآخر:** لأن التطبيق بدون تسجيل دخول، أي شخص يملك المفتاح العام (وهو معروف
لأي زائر) يقدر theoretically يقرأ أو يعدّل صفوف أي جهاز. للنسخة الحالية (طلاب +
بيانات نقاط وتقدم) هذا مقبول، لكن إن بغيت بحماية أقوى بالمستقبل:
- أضف تسجيل دخول بـ Supabase Auth (Email أو Google) واربط كل صف بـ `user_id`
  مع سياسة `auth.uid() = user_id` — ساعتها لا أحد يشوف إلا بياناته.

### 2) ⚠️ ترحيل المفاتيح الجديدة (مهم — نهاية 2026)
Supabase أوقفت إصدار المفاتيح القديمة على المشاريع الجديدة وستُجهز المفاتيح القديمة
نهاية 2026:

| النوع القديم | البديل الجديد | ملاحظة |
|---|---|---|
| `anon` (JWT طويل) | `sb_publishable_...` | يُستخدم في المتصفح، بديل مباشر |
| `service_role` (سرّي) | `sb_secret_...` | للأوامر الخلفية فقط — **لا تضعه أبداً بالكود** |

**المطلوب منك:** من **Settings ← API Keys** خذ مفتاح `sb_publishable_` واستبدله
مكان `SUPABASE_ANON_KEY` في `index.html` (سطر واحد). ما يحتاج أي تغيير ثاني —
السياسات المبنية على دور `anon` تظل شغالة مثل ما هي.

### 3) 🔴 نقطة حرجة خارج Supabase: مفتاح Groq داخل الكود
ملف `index.html` يحتوي مفتاح **Groq API** (لتوليد الكويزات والمحادثة) مكتوب نصاً
داخل صفحة تُرسل لكل زائر. أي شخص يقدر ينسخه ويستهلك رصيدك. **هذا أخطر بند بالإطلاق.**
التفاصيل والخيارات موجودة في [`LAUNCH_CHECKLIST.md`](../LAUNCH_CHECKLIST.md) ← قسم الأمان.

## 🧰 نصائح تشغيلية لمرحلة الإطلاق

| الموضوع | التوصية |
|---|---|
| **إيقاف المشروع تلقائياً** | الخطة المجانية توقف المشروع بعد أسبوع من عدم الاستخدام — أول يوم بالإطلاق راقب أن المؤشر أخضر، وفعّل زيارة دورية أو رقِّ للخطة Pro لو توقعت استخدام كثيف |
| **النسخ الاحتياطي** | الخطة المجانية بدون نسخ احتياطي تلقائي — كل فترة صدّر الجداول من Table Editor (CSV) أو شغّل `pg_dump` |
| **مراقبة الاستخدام** | راقب Dashboard ← Reports (طلبات API + حجم القاعدة). كل مزامنة = عدة طلبات REST |
| **Logs** | لو اشتكى طالب من عدم حفظ بياناته: Dashboard ← Logs ← PostgREST وشف الأخطاء مباشرة |
| **الحدود (Rate limits)** | الخطة المجانية تكفي لمئات الطلاب على الاستخدام الطبيعي، لكن واجهات Groq هي نقطة الاختناق الحقيقية وليس Supabase |
